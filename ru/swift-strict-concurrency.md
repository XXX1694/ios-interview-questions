### 1. Что проверяет strict concurrency в Swift 6 и чем языковой режим отличается от версии компилятора?

Она на этапе компиляции доказывает, что изменяемое состояние не достижимо из двух доменов изоляции одновременно: значение, пересекающее границу, либо `Sendable`, либо доказуемо передано. Версия компилятора определяет, какие проверки есть; языковой режим таргета определяет, будут ли они ошибками.

[Полный ответ →](https://irbisa.com/ru/topic/swift-strict-concurrency/#q-67017)

### 2. Что такое домен изоляции в Swift и как значение может перейти из одного домена в другой?

Доменом изоляции называют область, изменяемое состояние которой в каждый момент трогает одна задача: экземпляр актора, глобальный актор вроде `@MainActor`; `nonisolated`-код не принадлежит ни одному. Значение переходит между доменами, только если оно `Sendable` или передано без остатка.

[Полный ответ →](https://irbisa.com/ru/topic/swift-strict-concurrency/#q-67018)

### 3. Почему класс только с `let`-свойствами всё равно не `Sendable` и когда `@unchecked Sendable` будет честным решением?

Для класса `Sendable` не выводится: конформанс пишете вы, и класс должен быть `final`, с неизменяемыми Sendable-свойствами и без суперкласса, кроме `NSObject`. `@unchecked Sendable` снимает все проверки и честен, только если каждый доступ защищает ваш лок.

[Полный ответ →](https://irbisa.com/ru/topic/swift-strict-concurrency/#q-67003)

### 4. Swift 6 отклоняет оба объявления в `Services`. О чём говорит каждая ошибка и какие формы допустимы для разделяемого изменяемого состояния?

```swift
final class Analytics {
  var queue: [String] = []
}

enum Services {
  static var currentUserID: String?     // (1)
  static let analytics = Analytics()    // (2)
}
```

Строка (1) объявляет глобальную переменную, в которую может писать любой поток без сериализации. Строка (2) неизменяема, но указывает на не-Sendable класс с `var`-хранилищем, так что состояние за ней всё равно разделяемое. Любое исправление делает состояние неизменяемым, изолированным или защищённым.

[Полный ответ →](https://irbisa.com/ru/topic/swift-strict-concurrency/#q-67004)

### 5. Что `nonisolated(unsafe)` обещает компилятору и когда это честный ответ, а не способ заглушить ошибку?

Он выключает проверку конкурентности для одного объявления и обещает, что каждое обращение вы сериализуете сами; никакого лока и никакой защиты в рантайме он не добавляет. Честен он только тогда, когда рядом можно написать «это безопасно, потому что…» и показать механизм.

[Полный ответ →](https://irbisa.com/ru/topic/swift-strict-concurrency/#q-67002)

### 6. Почему класс с `Mutex` может быть `Sendable` без `@unchecked` и какие у `Mutex` ограничения?

`Mutex<Value>` (iOS 18+) представляет собой лок, который владеет защищаемым значением: значение достижимо только внутри `withLock`, а сам мьютекс `Sendable`, поэтому класс, который его хранит, конформит `Sendable` без `@unchecked`.

[Полный ответ →](https://irbisa.com/ru/topic/swift-strict-concurrency/#q-67019)

### 7. Найдите баг: этот `Sendable`-класс статистики без ошибок компилируется в Swift 6, но под нагрузкой счётчики выходят меньше, чем было вызовов `record`.

```swift
final class RequestStats: Sendable {
  private let storage = Mutex<[String: Int]>([:])

  var counts: [String: Int] {
    get { storage.withLock { $0 } }
    set { storage.withLock { $0 = newValue } }
  }

  func record(_ host: String) {
    counts[host, default: 0] += 1
  }

  func reset() { counts = [:] }
}
```

`counts[host, default: 0] += 1` проходит через геттер, а затем через сеттер, то есть берёт лок дважды: копирует словарь под одним локом, увеличивает копию без лока и записывает её обратно под другим. Параллельные вызовы затирают друг друга, и инкременты теряются.

[Полный ответ →](https://irbisa.com/ru/topic/swift-strict-concurrency/#q-67021)

### 8. Что такое глобальный актор и когда стоит объявлять свой вместо `@MainActor` или обычного `actor`?

Глобальный актор представляет собой один общий экземпляр актора, названный атрибутом, так что объявления из множества типов делят один домен изоляции; `@MainActor` служит встроенным примером. Свой стоит объявлять только для общепроцессного состояния, которое трогают несколько типов, например базы данных.

[Полный ответ →](https://irbisa.com/ru/topic/swift-strict-concurrency/#q-67009)

### 9. Что означает `nonisolated` на хранимом свойстве, на синхронном и на `async`-методе и уводит ли он работу с актора?

`nonisolated` выводит объявление из домена изоляции его актора: вызывающие обращаются к нему без `await`, а оно само не может трогать изолированное состояние. Это утверждение о проверках, а не о планировании; ни одна из трёх форм сама по себе не переносит работу в фоновый поток.

[Полный ответ →](https://irbisa.com/ru/topic/swift-strict-concurrency/#q-67012)

### 10. Скомпилируется ли этот код в языковом режиме Swift 6 и что изменится, если удалить строку с `print`?

```swift
final class Report {            // not Sendable
  var title = ""
}

actor Archive {
  private var reports: [Report] = []
  func store(_ r: Report) { reports.append(r) }
}

func archiveWeekly(_ archive: Archive) async {
  let report = Report()
  report.title = "Weekly"
  await archive.store(report)
  print(report.title)
}
```

В таком виде код не скомпилируется из-за ошибки *«sending 'report' risks causing data races»*: `report` читается после того, как его передали актору. Удалите `print`, и код скомпилируется: изоляция на основе регионов (SE-0414) доказывает, что после вызова до `report` больше ничто не дотянется.

[Полный ответ →](https://irbisa.com/ru/topic/swift-strict-concurrency/#q-67005)

### 11. Что может выразить параметр `sending`, чего не может `@Sendable`, и почему `Task.init` и `addTask` принимают `sending`-замыкания?

`@Sendable` ограничивает захваты замыкания Sendable-значениями, потому что оно может выполняться где угодно и сколько угодно раз. `sending` ничего не говорит о типе: он передаёт одно значение, причём вызывающий от него отказывается, а вызываемый получает его несвязанным.

[Полный ответ →](https://irbisa.com/ru/topic/swift-strict-concurrency/#q-67006)

### 12. После включения Approachable Concurrency в таргете скролл подтормаживает, пока эта модель декодирует картинки. Почему и как исправить?

```swift
@MainActor
final class GalleryModel {
  var thumbnails: [UIImage] = []

  func load(_ files: [Data]) async {
    for data in files {
      if let image = await Self.decode(data) { thumbnails.append(image) }
    }
  }

  nonisolated static func decode(_ data: Data) async -> UIImage? {
    UIImage(data: data)?.preparingForDisplay()
  }
}
```

С `NonisolatedNonsendingByDefault` (SE-0461, Swift 6.2) функция `nonisolated async` выполняется на акторе вызывающего, поэтому `decode` теперь работает на главном акторе и декодирует каждую картинку в главном потоке. Пометьте её `@concurrent`, чтобы вернуть на глобальный пул.

[Полный ответ →](https://irbisa.com/ru/topic/swift-strict-concurrency/#q-67020)

### 13. Как перевести большое приложение со Swift 5 на языковой режим Swift 6, не останавливая работу над фичами?

Таргет за таргетом, начиная с листьев графа зависимостей: в режиме Swift 5 включите полную проверку, чтобы каждое нарушение было предупреждением, доведите предупреждения до нуля, затем переключите этот таргет на Swift 6. Каждый шаг заканчивается зелёной сборкой, которую можно выпускать.

[Полный ответ →](https://irbisa.com/ru/topic/swift-strict-concurrency/#q-67001)

### 14. Что меняют в таргете Approachable Concurrency и изоляция `MainActor` по умолчанию и почему их не стоит включать в общем фреймворке?

Изоляция `MainActor` по умолчанию (SE-0466) делает каждое неаннотированное объявление `@MainActor`; Approachable Concurrency включает набор upcoming features, подходящих этой модели. В приложении это убирает большинство Sendable-ошибок; во фреймворке меняет изоляцию публичного API.

[Полный ответ →](https://irbisa.com/ru/topic/swift-strict-concurrency/#q-67013)

### 15. Ваша `@MainActor`-вью-модель должна конформить `Equatable`, а компилятор отклоняет конформанс. Почему и какие есть варианты?

`Equatable.==` объявлен как неизолированное требование: любой код может вызвать его синхронно из любого потока, а реализация на главном акторе этого обеспечить не может. Выходы: `nonisolated`-реализация, изолированный конформанс (Swift 6.2) или протокол, подходящий под изоляцию.

[Полный ответ →](https://irbisa.com/ru/topic/swift-strict-concurrency/#q-67007)

### 16. Что делает `@preconcurrency` на импорте и на конформансе протоколу и какой риск остаётся после того, как сборка позеленела?

На импорте он отключает диагностики об отсутствующем `Sendable` у типов этого модуля; на конформансе позволяет изолированному типу выполнить неизолированное требование, меняя ошибку компиляции на падение в рантайме. Ни то, ни другое гонку не убирает: одно её прячет, другое превращает в краш.

[Полный ответ →](https://irbisa.com/ru/topic/swift-strict-concurrency/#q-67008)

### 17. Колбэк вендора по документации приходит в главном потоке, но метод `nonisolated`. Когда `MainActor.assumeIsolated` уместен и когда он падает?

`assumeIsolated` в рантайме проверяет, что вы уже на главном акторе, а затем синхронно выполняет замыкание с изоляцией главного актора; поток он никогда не переключает. Он уместен, когда доставка в главном потоке гарантирована, и падает (в релизных сборках тоже), когда это не так.

[Полный ответ →](https://irbisa.com/ru/topic/swift-strict-concurrency/#q-67011)

### 18. Objective-C SDK вендора вызывает ваш делегат на произвольных потоках. Как встроить его в модуль Swift 6 без `@unchecked Sendable` повсюду?

Поставьте между SDK и своим кодом один маленький неизолированный объект: только его трогают потоки вендора, он не владеет изменяемым состоянием и пересылает каждое событие в `AsyncStream`, который потребляет изолированная модель. Граница пересекается в одном месте и Sendable-значениями.

[Полный ответ →](https://irbisa.com/ru/topic/swift-strict-concurrency/#q-67014)

### 19. Таргет чисто компилируется в режиме Swift 6, но Thread Sanitizer находит гонку данных. Чего не видит компилятор и как найти гонку?

Правы оба: Swift 6 доказывает, что незащищённое Swift-значение не пересекает границу изоляции в коде, который ему разрешили проверить, а TSan следит за реальными обращениями к памяти, включая код, который компилятор пропустил или не видел. Гонка живёт в этой слепой зоне.
