### 1. Что такое нотация Big O и как на лайвкодинге назвать сложность своего решения по времени и по памяти?

Big O описывает, как растут время работы или память алгоритма с ростом размера входа n: остаётся только самый быстрорастущий член, константы отбрасываются. На лайвкодинге называют оба показателя, например «O(n) по времени, O(n) дополнительной памяти», потому что более быстрое решение часто платит памятью.

### 2. Как `Set` или `Dictionary` превращают two-sum, поиск дубликатов или проверку на анаграмму из O(n²) в O(n) в Swift?

Вместо того чтобы сравнивать каждый элемент с каждым, запоминайте уже увиденное в хеш-таблице: `Set` или `Dictionary`. Поиск там в среднем стоит O(1), поэтому хватает одного прохода по входу, а платите вы O(n) дополнительной памяти.

### 3. Как реализовать стек и очередь на Swift и почему `Array.removeFirst()` плохо подходит для извлечения из очереди?

`Array` уже работает как стек: `append` кладёт элемент, `popLast()` снимает, оба за O(1). Очереди нужно ещё и O(1) в начале, а `removeFirst()` сдвигает все оставшиеся элементы, поэтому опустошить так очередь из n элементов стоит O(n²) в сумме.

### 4. Лайвкодинг: проверьте, что строка из скобок вроде `"([]{})"` сбалансирована. Какую структуру вы возьмёте и какие входы ломают наивное решение?

Стек: кладите каждую открывающую скобку, а на закрывающей снимайте верхнюю и проверяйте, что она парная. Строка сбалансирована, только если ни одна проверка не провалилась и в конце стек пуст. Один проход: O(n) по времени, O(n) памяти в худшем случае.

### 5. Лайвкодинг: слейте два отсортированных массива в один отсортированный за O(n + m), не вызывая `sorted()`. Какие есть пограничные случаи?

Идите по обоим массивам двумя индексами, добавляйте меньший из двух текущих элементов и сдвигайте его индекс; когда один массив закончится, допишите остаток другого. Каждый элемент читается один раз: O(n + m) по времени плюс O(n + m) на результат.

### 7. Как `Dictionary(grouping:by:)`, `reduce(into:)` и `uniquingKeysWith:` решают «сгруппировать анаграммы» и «посчитать слова» и в чём ловушка обычного `reduce`?

Они заменяют рукописный цикл «найти, вставить, если нет, добавить»: `Dictionary(grouping:by:)` раскладывает элементы по вычисленному вами ключу, `reduce(into:)` сворачивает всё в один словарь, который вы меняете на месте, а `uniquingKeysWith:` объединяет значения повторяющихся ключей.

### 8. Найдите баг: эта проверка на палиндром отвечает правильно, но на строке из 100 000 символов работает секунды.

```swift
func isPalindrome(_ s: String) -> Bool {
  var left = 0
  var right = s.count - 1
  while left < right {
    let l = s[s.index(s.startIndex, offsetBy: left)]
    let r = s[s.index(s.startIndex, offsetBy: right)]
    if l != r { return false }
    left += 1
    right -= 1
  }
  return true
}
```

`s.index(s.startIndex, offsetBy: k)` при каждом вызове идёт по строке с самого начала, потому что `Character` может занимать несколько байт, и цикл становится O(n²): миллиарды шагов для 100 000 символов, около 9 секунд в Release-сборке на Mac. Двигайте вместо этого два значения `String.Index`.

### 9. Какой алгоритм использует `sort()` в Swift, стабилен ли он и как отсортировать пользователей по убыванию очков, а затем по имени?

`sort()` реализует модифицированный timsort: O(n log n) в худшем случае, почти O(n) на почти отсортированном входе, и по документации он стабилен: равные элементы сохраняют свой порядок. Для нескольких ключей нужен один компаратор, который сравнивает главный ключ и при равенстве переходит к следующему.

### 10. Лайвкодинг: объедините пересекающиеся слоты вроде `[1, 3], [2, 6], [8, 10]`. Зачем сначала сортировать и нужно ли сливать соприкасающиеся `[1, 3]` и `[3, 5]`?

Отсортируйте слоты по началу и пройдите один раз: если слот начинается раньше, чем закончился последний объединённый, продлите тот до большего из концов, иначе начните новый слот. Сортировка стоит O(n log n) и перевешивает проход за O(n). Сливать ли соприкасающиеся слоты, зависит от того, включены ли концы.

### 11. Как техники двух указателей и скользящего окна превращают перебор за O(n²) в O(n)? Покажите на самой длинной подстроке без повторяющихся символов.

Обе заменяют вложенный цикл индексами, которые движутся только вперёд. Два указателя сходятся к середине отсортированного массива с обоих концов; скользящее окно держит непрерывный диапазон, расширяя правый край и сдвигая левый за то, что сделало окно невалидным. Каждый индекс проходит вход один раз: O(n).

### 12. Этот бинарный поиск на одних входах падает, а на других никогда не возвращается. Что с ним не так и какой инвариант цикла делает его правильным?

```swift
func indexOf(_ target: Int, in a: [Int]) -> Int? {
  var lo = 0
  var hi = a.count
  while lo <= hi {
    let mid = (lo + hi) / 2
    if a[mid] == target { return mid }
    if a[mid] < target {
      lo = mid
    } else {
      hi = mid - 1
    }
  }
  return nil
}
```

В нём смешаны два соглашения: `hi = a.count` задаёт полуоткрытую границу, а `lo <= hi` считает её закрытой, поэтому на пустом массиве код читает `a[0]` и падает; а когда `a[mid]` слишком мал, `lo = mid` оставляет `mid` в диапазоне, и как только `mid == lo`, ничего не меняется и цикл крутится вечно.

[Полный ответ →](https://irbisa.com/ru/topic/swift-coding-round/#q-74012)

### 13. Лайвкодинг: разверните односвязный список на месте. Продолжение: может ли освобождение списка из миллиона узлов переполнить стек в Swift, а глубокого дерева?

Пройдите список один раз, сохраняя `node.next` перед тем, как направить ссылку на `prev`: O(n) по времени, O(1) памяти. Со Swift 5.7 длинный список `Node` освобождается безопасно: цепочку `next` компилятор отпускает в цикле. Но глубокое дерево или список на `indirect enum` освобождаются рекурсивно и могут упасть.

### 14. Как обойти бинарное дерево в глубину и в ширину на Swift и какой обход подходит для «максимальной глубины», а какой для «обхода по уровням»?

Обход в глубину спускается по ветке до конца и только потом возвращается (рекурсия или явный стек); обход в ширину идёт уровень за уровнем. Максимальную глубину естественно считать через DFS: глубина узла на единицу больше, чем у его более глубокого поддерева. Обход по уровням по определению является BFS.

### 15. Лайвкодинг: реализуйте LRU-кэш с `get` и `put` за O(1). Какие две структуры вы совместите и почему одного `Dictionary` недостаточно?

`Dictionary` из ключа в узел находит запись за O(1), а двусвязный список хранит узлы в порядке использования, поэтому перенос узла в начало и удаление последнего сводятся к перестановке указателей за O(1). У одного словаря нет порядка, а массив ключей делает каждое обращение O(n).

### 17. В стандартной библиотеке Swift нет кучи. Как найти 100 самых частых слов в большом тексте и сколько стоит каждый подход?

Посчитайте слова в словаре за один проход O(n), затем выберите top k из u различных слов: отсортируйте все (O(u log u)), держите min-кучу из k записей (O(u log k)) или разложите их по корзинам по частоте (O(n + u)). Встроенной кучи в Swift нет: напишите маленькую сами или возьмите `Heap` из swift-collections.

### 18. Фича-модули объявляют, от каких модулей зависят. Как вычислить порядок сборки топологической сортировкой и как тот же проход находит цикл?

Представьте модули ориентированным графом и запустите алгоритм Кана: посчитайте у каждого модуля несобранные зависимости, начните с модулей, где их ноль, а после «сборки» модуля уменьшайте счётчик у зависящих от него и добавляйте тех, у кого он стал нулём. Оставшиеся в конце модули сидят на цикле или зависят от него.
