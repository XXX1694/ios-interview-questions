### 1. Как работает ARC в Swift и чем он отличается от сборщика мусора?

ARC освобождает экземпляр класса в тот момент, когда счётчик сильных ссылок на него падает до нуля; вызовы retain и release вставляет компилятор. Сборщик мусора, наоборот, ищет недостижимые объекты во время работы: это стоит пауз или фоновой работы, зато он освобождает и циклы ссылок, чего ARC не делает никогда.

[Полный ответ →](https://irbisa.com/ru/topic/ios-performance/#q-3501)

### 2. Чем стек отличается от кучи и какие значения Swift где хранятся?

Стек служит памятью конкретного потока: выделение в нём сводится к простому сдвигу указателя, а всё освобождается при возврате из функции. Куча представляет собой общую память, выделяемую через `malloc`: медленнее, а для экземпляров классов ещё и со счётчиком ссылок.

[Полный ответ →](https://irbisa.com/ru/topic/ios-performance/#q-63515)

### 3. Что такое retain cycle, откуда он берётся в iOS-коде и как его разорвать?

Retain cycle возникает, когда два или больше объекта держат друг друга сильными ссылками, поэтому ни один счётчик не доходит до нуля и все они утекают. Разрывают его, делая одну из связей `weak` или `unowned`, обычно обратную.

[Полный ответ →](https://irbisa.com/ru/topic/ios-performance/#q-3502)

### 4. Какими инструментами отладки Xcode вы пользуетесь каждый день и для чего нужен каждый: точки останова, LLDB, отладчик иерархии вью и Memory Graph?

Точки останова и LLDB останавливают приложение и показывают его состояние, Debug View Hierarchy объясняет вёрстку, Memory Graph находит утечки, а проверки времени выполнения в схеме ловят баги, которые видны только во время работы.

### 5. Какие из четырёх замыканий в этом view controller создают retain cycle, а какие только откладывают освобождение?

```swift
final class ProfileViewController: UIViewController {
  var onSave: (() -> Void)?
  private let saveButton = UIButton(type: .system)

  override func viewDidLoad() {
    super.viewDidLoad()
    view.addSubview(saveButton)
    UIView.animate(withDuration: 0.3) { self.view.alpha = 1 }                    // A
    URLSession.shared.dataTask(with: URL(string: "https://example.com/feed")!) { _, _, _ in self.reload() }.resume()  // B
    onSave = { self.reload() }                                                  // C
    saveButton.addAction(UIAction { _ in self.reload() }, for: .touchUpInside)  // D
  }

  func reload() {}
}
```

C и D создают циклы, A и B не создают. Все четыре сильно захватывают `self`, но A и B освобождаются после выполнения и могут разве что отложить `deinit`, а C и D хранит объект, которым владеет сам `self`, и петля замыкается.

[Полный ответ →](https://irbisa.com/ru/topic/ios-performance/#q-63520)

### 6. Найдите баг: Memory Graph показывает на один живой `OTPViewController` больше после каждого открытия и закрытия экрана ввода кода.

```swift
final class OTPViewController: UIViewController {
  private var timer: Timer?
  private var secondsLeft = 60

  override func viewDidLoad() {
    super.viewDidLoad()
    timer = Timer.scheduledTimer(timeInterval: 1, target: self,
                                 selector: #selector(tick), userInfo: nil, repeats: true)
  }

  @objc private func tick() {
    secondsLeft -= 1
    title = "Resend the code in \(secondsLeft) s"
  }
  deinit { timer?.invalidate() }  // the timer must not outlive the screen
}
```

Run loop удерживает запланированный таймер, а таймер удерживает свою цель `self`, поэтому после закрытия экрана счётчик контроллера не падает до нуля. `deinit`, единственное место с `invalidate()`, не выполняется: каждый заход оставляет утёкший контроллер, который продолжает тикать.

[Полный ответ →](https://irbisa.com/ru/topic/ios-performance/#q-63521)

### 7. Что такое утечка памяти в iOS-приложении и почему инструмент Leaks пропускает большинство утечек?

Утечкой называют память, которая приложению больше не нужна, но так и не освобождается. Инструмент Leaks показывает только объекты, до которых ничто не может дотянуться; на практике это retain cycle, а основной реальный рост памяти по-прежнему достижим из кэша, массива или синглтона и виден только в Allocations и Memory Graph.

[Полный ответ →](https://irbisa.com/ru/topic/ios-performance/#q-63514)

### 8. Как iOS-приложение должно реагировать на memory warning и почему `NSCache`, а не `Dictionary`?

Освободить всё, что можно пересоздать (кэши картинок, декодированные данные, тяжёлое состояние невидимых экранов), потому что система может убить процесс следующим шагом. `NSCache` делает значительную часть этого сам: он вытесняет объекты при нехватке памяти, а `Dictionary` только растёт.

[Полный ответ →](https://irbisa.com/ru/topic/ios-performance/#q-63516)

### 9. Пока работает этот цикл экспорта, память растёт до 1,5 ГБ и падает сразу после его завершения. Почему и как это исправить?

```swift
func exportThumbnails(_ urls: [URL], to folder: URL) throws {
  for url in urls {                                   // 3 000 photos
    guard let image = UIImage(contentsOfFile: url.path),
          let thumb = image.preparingThumbnail(of: CGSize(width: 512, height: 512)),
          let data = thumb.jpegData(compressionQuality: 0.8)
    else { continue }
    try data.write(to: folder.appendingPathComponent(url.lastPathComponent))
  }
}
```

Цикл заполняет autorelease pool, который очищается только в конце текущего оборота run loop или рабочего блока, поэтому временные картинки и данные каждой итерации живут до завершения всего цикла. Если обернуть тело цикла в `autoreleasepool { }`, пул будет очищаться на каждой итерации.

[Полный ответ →](https://irbisa.com/ru/topic/ios-performance/#q-63517)

### 10. Почему большинство проблем с памятью в iOS-приложениях связано с изображениями и как их даунсемплить?

Декодированное изображение занимает ширина × высота × 4 байта, каким бы маленьким ни был файл, поэтому 12-мегапиксельное фото занимает около 48 МБ в памяти, даже если JPEG весит 2 МБ. Даунсемплинг через ImageIO декодирует сразу в размер отображения, и полный bitmap вообще не появляется.

[Полный ответ →](https://irbisa.com/ru/topic/ios-performance/#q-63501)

### 11. Пользователь закрывает этот экран, запросы продолжают уходить, а `deinit` так и не печатается. Что делает этот `Task`?

```swift
@MainActor
final class FeedModel {
  var posts: [Post] = []

  init(feed: FeedService) {
    Task {
      for await update in feed.updates {   // a stream that never finishes
        self.posts = update
      }
    }
  }

  deinit { print("FeedModel freed") }      // never prints
}
```

`Task` сильно держит `self`, пока выполняется его тело, а цикл `for await` не заканчивается, потому что стрим никогда не завершается. Задачу никто не хранит и не отменяет, поэтому она держит модель живой вечно.

[Полный ответ →](https://irbisa.com/ru/topic/ios-performance/#q-63508)

### 12. Как найти проблему производительности с помощью Instruments, а не угадывать?

Воспроизведите медленный сценарий на реальном устройстве в Release-сборке, запишите его шаблоном, подходящим под симптом, и меняйте по одной вещи за раз, сравнивая один и тот же трейс до и после. Симулятор работает на CPU вашего Mac, поэтому его тайминги ничего не значат.

### 13. Чем hang отличается от hitch и как сохранить отзывчивость главного потока?

Hitch означает кадр, показанный с опозданием: заметное подёргивание при скролле или анимации. При hang главный поток заблокирован на 250 мс и дольше, так что тапы не получают ответа. Оба обычно означают слишком много работы на главном потоке; лечится это переносом работы с него и укладыванием каждого кадра в бюджет.

[Полный ответ →](https://irbisa.com/ru/topic/ios-performance/#q-3504)

### 14. Как добиться плавного скролла в `UITableView` или `UICollectionView`?

Укладывайте работу каждой ячейки в бюджет кадра (около 16 мс при 60 Гц и 8 мс при 120 Гц): переиспользуйте ячейки, загружайте и декодируйте картинки вне главного потока в размере отображения и избегайте работы с layout и рендерингом, которая повторяется каждый кадр.

[Полный ответ →](https://irbisa.com/ru/topic/ios-performance/#q-3505)

### 15. Что такое offscreen rendering, какие свойства слоя его вызывают и как его найти?

Offscreen rendering означает, что GPU рисует поддерево слоёв в отдельный буфер и потом композитит его обратно, потому что не может нарисовать его за один проход. Его вызывают маски, тени без `shadowPath`, групповая прозрачность и `shouldRasterize`, и цена повторяется каждый кадр для каждого такого слоя.

[Полный ответ →](https://irbisa.com/ru/topic/ios-performance/#q-63511)

### 16. Пользователи жалуются на крэши, которые у вас не воспроизводятся. Как дойти от крэш-репорта до строки кода?

Символизируйте репорт dSYM-файлом именно этой сборки, а затем прочитайте тип исключения и стек упавшего потока. Тип исключения подсказывает, что это за баг, ещё до того, как вы откроете код.

[Полный ответ →](https://irbisa.com/ru/topic/ios-performance/#q-63518)

### 17. Что означает `EXC_BAD_ACCESS` и какие инструменты Xcode помогают найти причину?

Приложение обратилось к памяти, к которой нельзя: к освобождённому объекту, висячему указателю или неотображённому адресу. Строка крэша часто лишь место, где повреждение заметили, поэтому нужны инструменты, которые останавливают приложение в момент самого неверного обращения.

### 18. В крэш-репорте код исключения `0x8badf00d` и ни одного кадра вашего кода. Что убило приложение и что обычно к этому приводит?

Его убил watchdog: приложение не завершило переход жизненного цикла (запуск или возврат на передний план) за отведённое время, поэтому система прислала `SIGKILL` и пометила отчёт кодом `0x8badf00d` («ate bad food»).

[Полный ответ →](https://irbisa.com/ru/topic/ios-performance/#q-63509)

### 20. Как Core Animation превращает изменения UI в кадр и почему спиннер продолжает крутиться, когда главный поток завис?

### 21. Индикатор памяти Xcode показывает 480 МБ, Allocations показывает 90 МБ, а приложение всё равно убивают из-за памяти. Какая цифра настоящая?

Цифра индикатора. Лимит памяти система применяет к `phys_footprint` (всей грязной и сжатой памяти процесса), а Allocations показывает в основном то, что прошло через `malloc` и рантаймы объектов, и пропускает крупные регионы памяти вне malloc-кучи.

[Полный ответ →](https://irbisa.com/ru/topic/ios-performance/#q-63512)

### 22. Как измерить и сократить время запуска приложения?

Измерьте холодный запуск до первого кадра на реальных устройствах и сокращайте две фазы по отдельности: работу `dyld` и рантайма до `main` и ваш собственный код от `main` до отрисовки первого экрана. Apple советует ориентироваться на первый кадр примерно за 400 мс.

### 23. Тестировщики говорят, что приложение сажает батарею. Как найти причину и что на самом деле менять?

Энергия уходит в основном на пробуждение железа (сотового модуля, GPS, GPU и CPU), а не на выполнение кода, поэтому исправления сводятся к тому, чтобы делать работу реже и пачками. Сначала измерьте на устройстве: обычно причиной оказывается одна подсистема, которую забыли остановить.

[Полный ответ →](https://irbisa.com/ru/topic/ios-performance/#q-63503)

### 24. Размер загрузки приложения растёт с каждым релизом. Как найти, что занимает место, и сократить его?

Измерьте то, что пользователи реально скачивают (размеры по устройствам в App Store Connect или App Thinning Size Report из Xcode), и атакуйте самую большую часть: обычно это ресурсы, затем сторонний код. `.ipa` на вашем Mac содержит варианты для всех устройств, и это не та цифра.

[Полный ответ →](https://irbisa.com/ru/topic/ios-performance/#q-63504)

### 25. Что такое thread explosion и как Swift Concurrency его избегает, при условии, что вы не блокируете задачу?

Взрыв потоков (thread explosion) случается, когда работа, отправленная на конкурентную очередь, блокируется, и GCD запускает ещё один поток для следующего элемента, потом ещё один. Десятки почти всё время заблокированных потоков тратят память и CPU на переключение контекста вместо работы.

[Полный ответ →](https://irbisa.com/ru/topic/ios-performance/#q-63505)
