### 1. Что такое MVC в UIKit и почему он так часто превращается в Massive View Controller?

В MVC от Apple контроллер связывает модель и view, но `UIViewController` ещё и владеет жизненным циклом своей view, поэтому вёрстка, состояние, сеть и навигация оседают в одном классе, который нельзя протестировать без view.

[Полный ответ →](https://irbisa.com/ru/topic/ios-architecture/#q-3202)

### 2. Что такое внедрение зависимостей и как оно делает view model тестируемой?

Внедрение зависимостей (dependency injection) означает, что объект получает свои зависимости снаружи, а не создаёт и не ищет их сам. Передавайте их через `init` как протоколы, и тест подставит заглушку там, где приложение передаёт настоящий клиент.

[Полный ответ →](https://irbisa.com/ru/topic/ios-architecture/#q-3204)

### 3. Что такое MVVM, какую проблему он решает и как выглядит в UIKit и в SwiftUI?

MVVM выносит логику представления и состояние экрана из view во view model, которая отдаёт готовые к показу значения; view только привязывается к ним и передаёт события пользователя, поэтому логику можно покрыть юнит-тестами без всякого UI.

[Полный ответ →](https://irbisa.com/ru/topic/ios-architecture/#q-63203)

### 4. Найдите баг: если быстро набрать `"iphone"`, в списке иногда остаются результаты для `"iph"`.

```swift
@MainActor @Observable
final class SearchViewModel {
  private(set) var results: [Product] = []
  private let api: any ProductAPI & Sendable
  init(api: any ProductAPI & Sendable) { self.api = api }

  func queryChanged(_ query: String) {
    Task {
      let found = (try? await api.search(query)) ?? []
      results = found
    }
  }
}
```

Каждое нажатие клавиши запускает свой `Task`, и старые никто не отменяет, поэтому побеждает ответ, который пришёл последним: медленный ответ для `"iph"` приходит после быстрого для `"iphone"` и перезаписывает `results` устаревшими данными.

[Полный ответ →](https://irbisa.com/ru/topic/ios-architecture/#q-63223)

### 5. Делегат, замыкание, NotificationCenter, KVO, Combine или AsyncSequence: как выбрать способ общения двух объектов?

Выбирайте по форме связи: несколько сообщений одному известному собеседнику отправляют через делегат, один результат возвращают `async`-вызовом, а многих неизвестных слушателей оповещают нотификацией или наблюдаемым значением.

[Полный ответ →](https://irbisa.com/ru/topic/ios-architecture/#q-63206)

### 6. Какие классические паттерны проектирования используют UIKit и Foundation и где их видно?

В UIKit и Foundation собран каталог классических паттернов: делегат и target-action для колбэков, наблюдатель через NotificationCenter и KVO, синглтоны для общих сервисов приложения, компоновщик для дерева view и цепочка обязанностей для responder chain.

### 7. Что такое принципы SOLID, с примером из iOS для каждого?

SOLID объединяет пять правил, которые держат типы маленькими и заменяемыми: одна причина для изменения, расширение без правки, подтип соблюдает контракт, маленькие протоколы, зависимость от абстракций. В iOS это в основном аргументы против massive view controller.

[Полный ответ →](https://irbisa.com/ru/topic/ios-architecture/#q-63216)

### 8. Что такое паттерн Coordinator и когда он оправдан?

Координатором называют объект, который владеет навигацией флоу: экраны сообщают о событиях вроде «логин прошёл», а координатор решает, что показать дальше, поэтому view controller-ы никогда не пушат и не презентуют друг друга.

[Полный ответ →](https://irbisa.com/ru/topic/ios-architecture/#q-3203)

### 9. После каждого завершённого оформления заказа его `CheckoutCoordinator` остаётся в памяти. Что не так в этом коде?

```swift
@MainActor
final class AppCoordinator {
  private var children: [AnyObject] = []
  private let nav: UINavigationController
  init(nav: UINavigationController) { self.nav = nav }

  func showCheckout() {
    let checkout = CheckoutCoordinator(nav: nav)
    checkout.onFinish = {
      self.nav.popToRootViewController(animated: true)
    }
    children.append(checkout)
    checkout.start()
  }
}
```

Дочерний координатор добавляется в `children`, но никогда оттуда не удаляется, поэтому родитель держит каждое завершённое оформление вместе с его view controller-ами и черновиком. Вдобавок замыкание сильно захватывает `self` и создаёт цикл через `children`.

[Полный ответ →](https://irbisa.com/ru/topic/ios-architecture/#q-63219)

### 10. Пуш-уведомление должно открыть конкретный комментарий к конкретному посту. Где живёт это состояние навигации?

В одном наблюдаемом объекте-роутере выше навигационного контейнера: он хранит типизированный массив path, который меняют обработчик ссылок, обработчик уведомлений и сам UI.

[Полный ответ →](https://irbisa.com/ru/topic/ios-architecture/#q-63201)

### 11. Что такое паттерн Repository и зачем держать DTO, доменные модели и состояние экрана отдельными типами?

Репозиторий представляет собой протокол на доменное понятие, который прячет, откуда пришли данные (сеть, база, кэш), и отдаёт доменные типы. DTO остаются за ним, поэтому переименованное поле в JSON становится правкой в одном файле, а не в трёх экранах.

[Полный ответ →](https://irbisa.com/ru/topic/ios-architecture/#q-63210)

### 12. Когда DI-контейнер вроде Swinject или Factory оправдан по сравнению с обычным внедрением через конструктор?

Редко: внедрение через конструктор из composition root проверяется компилятором и достаточно для большинства приложений. Рантайм-реестр вроде Swinject окупается только при десятках сервисов и областях жизни, а его цена в том, что отсутствующая регистрация падает на старте приложения, а не на сборке.

### 13. Найдите баг: `testFreshInstallShowsOnboarding` проходит отдельно на чистом симуляторе, но падает после прогона всего класса, и дальше падает всегда.

```swift
@MainActor final class OnboardingViewModel {
  private let defaults: UserDefaults
  init(defaults: UserDefaults = .standard) { self.defaults = defaults }
  var showsOnboarding: Bool { !defaults.bool(forKey: "onboardingDone") }
  func finish() { defaults.set(true, forKey: "onboardingDone") }
}
@MainActor final class OnboardingTests: XCTestCase {
  func testFreshInstallShowsOnboarding() {
    XCTAssertTrue(OnboardingViewModel().showsOnboarding)
  }
  func testFinishHidesOnboarding() {
    let model = OnboardingViewModel()
    model.finish()
    XCTAssertFalse(model.showsOnboarding)
  }
}
```

Оба теста используют `UserDefaults.standard` по умолчанию, а он сохраняется на диск. `testFinishHidesOnboarding` записывает `onboardingDone = true`, и каждый следующий запуск другого теста (в этом прогоне или в следующем) читает это оставшееся значение вместо чистой установки.

[Полный ответ →](https://irbisa.com/ru/topic/ios-architecture/#q-63224)

### 14. Как VIPER и Clean Swift (VIP) делят экран и что даёт эта церемония?

Оба делят экран на объекты с одной обязанностью, связанные протоколами (VIPER на View, Interactor, Presenter, Entity и Router, Clean Swift на односторонний цикл ViewController → Interactor → Presenter), и дают тестируемые швы и единообразную форму ценой примерно пяти файлов на экран.

[Полный ответ →](https://irbisa.com/ru/topic/ios-architecture/#q-63212)

### 15. Что такое feature flags и как с их помощью безопасно выкатить рискованное изменение?

Feature flag работает как переключатель во время выполнения, который решает, активен ли код, уже лежащий в бинарнике. Так можно мержить незаконченную работу, раскатывать фичу на долю пользователей и выключать её удалённо, не дожидаясь App Review.

[Полный ответ →](https://irbisa.com/ru/topic/ios-architecture/#q-63220)

### 16. Сравните MVC, MVP, MVVM, VIPER и TCA: как выбрать архитектуру для фичи или команды?

Они различаются тем, где живёт логика, не относящаяся к view, и насколько строго течут данные: MVC держит её в контроллере, MVP и MVVM выносят в тестируемый объект, VIPER дробит дальше, TCA проводит каждое изменение через reducer. Выбирают по команде, UI-фреймворку и тому, что нужно тестировать.

[Полный ответ →](https://irbisa.com/ru/topic/ios-architecture/#q-3201)

### 17. Что такое однонаправленный поток данных и какие проблемы решает с его помощью TCA?

Однонаправленный поток данных (unidirectional data flow) означает, что состояние меняется только в одну сторону: view отправляет action, reducer вычисляет новое состояние, view его отрисовывает. TCA, Redux-подобная библиотека от Point-Free, строит так каждую фичу из State, Action, Reducer, Effect и Store.

[Полный ответ →](https://irbisa.com/ru/topic/ios-architecture/#q-3205)

### 18. Что такое Clean Architecture в iOS и когда слой use case окупается?

Clean Architecture раскладывает код по кольцам (в центре домен, вокруг данные и представление), и все зависимости направлены внутрь, поэтому бизнес-правила ничего не знают об URLSession, SwiftData или SwiftUI и тестируются отдельно.

[Полный ответ →](https://irbisa.com/ru/topic/ios-architecture/#q-63202)

### 19. Как структурировать большое iOS-приложение (по фичам или по слоям) и где проводить границы модулей?

Сначала делите по фичам, а внутри фичи уже по слоям: локальный Swift-пакет на каждую фичу поверх общих модулей Core и DesignSystem и тонкий app-таргет, который только связывает их между собой.

[Полный ответ →](https://irbisa.com/ru/topic/ios-architecture/#q-3206)

### 20. Оформление заказа из трёх шагов делит один черновик, и пользователи жалуются, что новый заказ открывается с адресом из предыдущего. Где должен жить этот черновик?

В объекте, которым владеет сам флоу: он создаётся при старте флоу и освобождается при его завершении. Старый адрес означает, что черновик пережил флоу, а именно это и гарантируют синглтон или environment-объект на корне приложения.

[Полный ответ →](https://irbisa.com/ru/topic/ios-architecture/#q-63214)

Внедряйте SwiftUI целыми экранами через `UIHostingController`, чтобы шов проходил по границе навигации, а не внутри вью.

Рефакторьте по швам, которых вы и так касаетесь: новое пишется в целевой архитектуре, а старые экраны меняются только когда в них приходит задача.

### 23. Как бы вы спроектировали конвейер загрузки и кэширования картинок для прокручиваемой ленты?

По слоям: кэш в памяти для декодированных и уменьшенных картинок, кэш на диске для исходных байтов и загрузчик, который склеивает одинаковые запросы, декодирует вне главного потока и отменяет работу для ячеек, ушедших с экрана.

### 24. Как бы вы спроектировали offline-first синхронизацию для приложения заметок, включая разрешение конфликтов?

Сделайте локальную базу источником истины: UI читает и пишет только локально, каждое изменение дополнительно ставится в очередь исходящих (outbox), а движок синхронизации, когда может, отправляет outbox и забирает изменения с сервера, разрешая конфликты по заранее выбранному правилу.
